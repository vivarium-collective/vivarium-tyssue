# Coupling-hierarchy geometries (viva-lumenoid)

Inventory + additions for the viva-lumenoid multiscale campaign (epithelial
vertex model coupled to a collagen-IV basement membrane). The campaign needs a
hierarchy of geometry levels for the coupling; this is what already existed vs.
what was added.

## Inventory — what stock tyssue already provides

`vivarium_tyssue.core_maps.GEOMETRY_MAP` already wraps `tyssue.geometry.*` and
exposes `PlanarGeometry`, `SheetGeometry`, `AnnularGeometry`,
`MonolayerGeometry`, `ClosedMonolayerGeometry`, `ClosedSheetGeometry`,
`BulkGeometry`, `CylinderGeometry`, and the fork-only `VesselGeometry` /
`RNRGeometry`. Mapping those onto the coupling hierarchy:

| Level | Hierarchy stage        | Status      | Class |
|-------|------------------------|-------------|-------|
| 1 | 2D planar sheet            | **existed** | `PlanarGeometry` / `SheetGeometry` |
| 2 | 2D cross-section (height)  | **added**   | `CrossSectionGeometry` |
| 3 | 3D monolayer               | **existed** | `MonolayerGeometry` |
| 4 | closed 3D lumenoid + BM    | **added**   | `LumenoidGeometry` |

`AnnularGeometry` gave a 2D ring cross-section with a lumen area, and
`ClosedMonolayerGeometry` gave a closed monolayer that tracks an enclosed
`lumen_vol` — but neither exposed the two things the campaign needs: a direct
per-cell **height** DOF with basal adhesion (level 2), and a lumen
**pressure** plus a named **basal BM coupling surface** (level 4). Those are the
genuinely missing pieces, added in `vivarium_tyssue/geometries.py`.

## Added classes (`vivarium_tyssue/geometries.py`)

### `CrossSectionGeometry` (level 2)
Thin class over tyssue's 2D annular machinery (`AnnularGeometry`). Adds:
- `face_df['height']` + `settings['mean_cell_height']` — each cell's apico-basal
  height as an explicit, directly-readable DOF (apical-vs-basal vertex centroid
  distance; falls back to the apico-basal-axis extent).
- `vert_df['basal_offset']` + `settings['basal_adhesion_strain']` — basal
  vertices tracked against a substrate reference radius (`settings['basal_radius']`).
- Lumen area via the `segment` edge labels, so it also works on a plain `Sheet`.

### `LumenoidGeometry` (level 4)
Builds on `ClosedMonolayerGeometry`. Adds:
- `settings['lumen_pressure']` — Laplace-type pressure `P = lumen_elasticity *
  (V0 - V)` from the tracked lumen volume `V` and a prefered volume `V0` (seeded
  from the first observed volume, so the lumen starts at rest).
- `settings['bm_surface_area']` / `settings['bm_face_count']` and the
  `basal_shell(eptm)` / `bm_surface(eptm)` accessors — the outward basal surface
  the collagen BM couples to, exposed for an external BM process to read/write.
- `settings['lumen_side']` (default `basal`) names the lumen-lining segment;
  `settings['bm_side']` names the BM shell (defaults to the complementary side).

## Reaching them from the composite / dashboard layer

Both are registered in `GEOMETRY_MAP` under the names **`CrossSectionGeometry`**
and **`LumenoidGeometry`**, selectable by name in any `EulerSolver` composite's
`config.geom`. Two minimal composites exercise them end to end:
`vivarium_tyssue/composites/cross_section.composite.yaml` and
`lumenoid.composite.yaml` (small meshes generated by
`scripts/gen_geometry_datasets.py` into `workspace/datasets/`).

Invariants are covered by `tests/test_geometry_classes.py`.
